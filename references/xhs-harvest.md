# 阶段一：小红书检索与评论挖掘

目标：把「主题相关的帖子」和「帖子里留了联系方式的人」这两层都拿全，并且每条都带得出时间戳。

## 1. 关键词

用目标人群自己的口语说法。同一批任务准备 3~6 个变体，逐个搜，结果合并去重。

以「WhatsApp 互养号」为例，实测有量的是：

- `whatsapp 互养号`（最全）
- `wa互`（短，召回差，会掺推荐流）
- `whatapp 养号互加`（错拼变体常有内容）
- `whatsapp 养号搭子`
- `whatsapp 新号 不敢加人`

判别标准：搜索结果里如果连续 6 张卡片都跟主题无关，说明这个词没量或被降权，换词，不要往下翻。

## 2. 筛选面板怎么点

网页版搜索页右上角「筛选」，展开后有四组：

| 组 | 取值 | 建议 |
|---|---|---|
| 排序依据 | 综合 / 最新 / 最多点赞 / 最多评论 / 最多收藏 | 用**综合** |
| 笔记类型 | 不限 / 视频 / 图文 | 不限 |
| 发布时间 | 不限 / 一天内 / 一周内 / 半年内 | 先试**一天内**，为空则升到一周内 |
| 搜索范围 | 不限 / 已看过 / 未看过 / 已关注 | 不限 |

**关键坑：排序选「最新」会毁掉相关性。** 当「最新 + 一天内」同时开启时，因为当日匹配内容稀少，平台会填充推荐流，返回一堆与关键词无关的笔记（会看到完全不相关的穿搭、理财、宠物内容）。此时正确做法是：

1. 排序留在**综合**；
2. 时间设**一天内**；看是否还有相关结果；
3. 若相关结果 < 3 条，时间改回**不限**，靠读卡片时间戳自己筛。

筛选生效后按钮会变成「已筛选」。用完记得点「重置」或把时间改回「不限」，否则下一次搜索会继承这个限制。

## 3. 读卡片上的时间戳

卡片作者名下方那行就是发布时间，格式三种：

- `x分钟前` / `x小时前` —— 当天
- `昨天` —— 约 24 小时内
- `MM-DD` —— 更早（结合帖子内容判断年份）

`1天前` 这种写法通常出现在 24~48 小时区间。想找「刚发的」，就只保留 `x分钟前` / `x小时前` / `昨天` / `1天前` 四类。

## 4. 翻评论的正确姿势

点开帖子后是「左图右评论」布局，评论在右侧面板，滚动面板而不是滚动整页。

每条评论包含四要素，全部要记：

```
昵称 | 评论时间 | 地区 | 正文（含号码）
```

时间格式与卡片一致（`x小时前` / `昨天 HH:MM` / `MM-DD`）。

**必须注意的分层现象（实测）：**

| 评论时间 | 正文里有没有号码 | 典型措辞 |
|---|---|---|
| 3~11 小时前 | 基本没有 | 「加我」「每天在线」「111」「私信我」 |
| 13~24 小时前 | 约一半有 | 「我每天都在线 +86 132xxxxxxx」 |
| 1 天以上 | 多数有明文号码 | 「+60 12-345 6789 求加」 |

原因：平台对近期评论做号码抑制。所以：

- 想快速拿到**号码**，往老评论翻；
- 想拿到**最新意向**，新评论只能作为「活跃度证据」，号码要么等对方回私信，要么看他附的图片。

## 5. 评论区图片 = 二维码矿

带图片的评论常直接贴 WhatsApp 二维码（截图自手机 App 的「分享二维码」）。识别特征：

- 评论正文很短（「有没有人加我呀」）但附了一张竖版图片；
- 图片里有头像 + 明显二维码方块 + 「WhatsApp contact」字样。

这类评论的新鲜度往往最高（用户就是为加人才贴的）。处理方式见 `qr-decode.md`。

## 6. 批量抽取

把读到的评论逐条追加到一个 UTF-8 文本文件（每条一行，用 `|` 分隔四要素），然后：

```bash
python scripts/extract_contacts.py comments.txt --out leads_raw.csv
```

脚本会抽出号码并规范化，但与「评论者/时间/地区」的对应关系需要用 `|` 分隔的行结构保留，因此**一行一条评论**这个格式不要破坏。

## 7. 记录建议字段

```
号码 | 昵称 | 来源帖标题 | 来源帖URL | 评论时间 | 地区 | 渠道(明文/二维码) | 备注
```

来源帖 URL 一定要留，它是后续复盘和合规说明的唯一凭据。
